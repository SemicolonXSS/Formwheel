폴리리듬은 내보내기에 화면의 1.8~8초·0.1초 단위를 적용하지 않아 다시 불러올 때 회전 주기가 바뀌었다. 화면·저장·가져오기가 같은 정규화 함수를 사용하도록 했다. JSON은 2MB를 넘으면 읽기 전에 거절하고 문서화된 version 1을 확인한다. 이전 파일의 읽기나 오류가 새 파일·편집·닫기 동작보다 늦게 도착해 현재 맵이나 상태를 덮어쓰는 문제는 가져오기 세대 번호로 막았다. 이 작업은 이전 녹화 오디오 준비 취소 수정과 다른 파일 읽기 경로다.

클릭커는 손상된 저장 기록을 읽으면 기본값으로 돌아간 뒤 시작 시 저장이 원본을 덮어썼다. 이제 원본을 유지하고 손상·미지원 기록은 복구 선택 전까지 플레이를 멈춘다. 원본 내려받기와 **원본 백업 후 새 게임 시작**을 제공한다. 원본을 별도 키에 쓰고 다시 읽어 확인한 뒤 기본 저장을 교체한다. 백업 실패나 다른 탭의 새 기록이 발견되면 원본을 바꾸지 않는다. 최근 원본 백업은 다음 접속에서도 내려받을 수 있다. 저장소를 읽을 수 없을 때는 이 탭의 임시 플레이를 허용하며 저장 쓰기를 막는다. 기존 저장 형식의 10,000자리 숫자 한계로 표현할 수 없는 강화 지수도 계산 전에 거절하며 원본을 잘라내지 않는다.

클릭커 순위는 빈 목록·읽기 실패 후 남아 있던 내 순위를 지우고, 101자리 형식이어도 문서상 최대인 1e100을 넘는 점수는 제외한다. 여러 새로고침이 겹치면 가장 최근 요청만 결과나 오류를 표시한다. 조회 상한 20명과 등록 정책·점수 지급량은 그대로다. 원본 다운로드·다음 세션의 백업 접근·저장 공간 부족·다른 탭의 변경·임시 플레이·역순 응답 및 복구 화면 axe를 격리된 브라우저에서 검증했다.

PVP는 제작 화면과 플레이 화면이 같은 작은 자료 검증 모듈을 사용한다. 목록 하나가 잘못된 형식이어도 나머지 정상 자료는 읽고, 이름·ID·타입·정수 범위·예산·시작점 및 보관 한도를 일관되게 검사한다. 끝난 경기의 오래된 레지스트리 항목은 제거하고 진행 중 경기의 정의는 유지한다. 공유 맵의 ID가 다른 기존 맵과 충돌하면 원본을 보존하고 별도 사본으로 가져온다. 이 묶음은 이전 Studio의 중복 시작점 검사와 다른 **플레이·공유 가져오기 경로**를 포함한다.

PVP 체력 막대는 실제 최대 체력 대신 205/175를 사용해 가득 찬 체력도 부족하게 보였다. 각 플레이어의 실제 최대값을 솔로·온라인 렌더러가 먼저 전달하고 HUD가 각각의 비율을 사용한다. 제품에 있는 **무기 10종·스킬 8종·허용 속도 투자로 만드는 274개 유효 조합 전체**에서 가득 찬 체력 100%와 절반 체력 50%를 검사했다. 이 조합 수를 버그 수로 세지 않았다. 애니메이션을 멈추고 실제 엔진과 DOM 관찰자를 재생한 검사이며 274번의 실제 경기를 치렀다는 뜻이 아니다. 온라인은 host/guest별 표시를 SDK 대역으로 확인했다.

Studio 테스트 탭을 나가면 경기와 눌린 입력을 중지한다. 탄환은 남은 수명만큼만 마지막 프레임을 이동하며, AI 근접 공격에도 활성 보호막의 피해 차단을 적용한다. 보호막 종료 뒤 정상 피해가 들어가는 대조 검사도 포함했다.

수정 전에는 새 시나리오 308개 중 307개가 실패했고 수정 후 실패는 0개다. 빈 회전 주기의 기본값 검사는 원래도 통과한 회귀 보호 사례다. 기존 900개·450개 묶음, 폴리리듬 2,880노트, PVP 504개 키보드 편집·내보내기·포인터·터치·저장, 10개 배치 axe와 6개 AI 실행 검사도 통과했다. 루트 구문 154개 블록/파일, 카탈로그 75개 프로젝트·사이트맵 40개 URL, 55개 페이지 탐색, Node 테스트 11개 파일, 클릭커 구문·로컬 참조 16개 및 리더보드 테스트가 통과했다. 직전 루트 PR #38 CI 전체 성공을 확인했다.

```sh
FW_ECOSYSTEM_ROOT=/path/to/checkouts node tests/data-recovery-regression.cjs
```

위 경로 아래 `Formwheel_Clicker`와 `Formwheel_PVP`, 그리고 Playwright·axe·Chromium이 필요하다. 기본값은 루트 저장소 상위 폴더다. 외부 HTTP/WebSocket과 서비스 워커는 차단한다. 순위 읽기는 순서를 제어하는 대역을 사용하고 SDK 쓰기는 호출 시 실패하도록 막았다. 테스트용 내부 함수 접근은 HTTP 응답에만 삽입하며 제품에는 넣지 않았다. 앱 스크립트 캐시 버전도 갱신했다.

CI는 두 앱의 수정 커밋을 고정하고 기존 검사와 새 검사 결과를 함께 보관한다. 이 보고서 작성 시 새 CI는 실행 전이다. 운영 데이터 쓰기·병합·배포를 수행하지 않았다. 실제 기기·스크린리더·전체 온라인 경기 검증을 대신하지 않는다.
