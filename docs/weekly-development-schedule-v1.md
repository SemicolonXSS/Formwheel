# Formwheel 공식 주간 개발 일정 v1.0

운영 방식: **B안 — 요일별 기본 역할 고정, 세부 작업 매주 변경**

## 주간 일정
| 요일 | 명칭 | 주요 활동 | 권장 시간 |
|---|---|---|---|
| 월 | GOAL DAY | 주간 목표 3개, 우선순위, 세렌 선정 | 20~30분 |
| 화 | FIX DAY | 주요 버그 수정, 회귀 테스트 | 20~40분 |
| 수 | HUB DAY | 검색·카드·모바일 탐색 개선 | 30~45분 |
| 목 | SEREN DAY | 아이디어 제안·선정·소규모 구현 | 30~45분 |
| 금 | CHECK DAY | 전체 점검, 방문자·체류시간 분석 | 40~60분 |
| 토 | BUILD DAY | 집중 개발 및 테스트 | 1~2시간 |
| 일 | UPDATE DAY | 통합 테스트, 검증된 변경 반영, 회고 | 2~3시간 |

시간은 권장 가이드이며 학업과 휴식이 우선이다.

## 운영 원칙
1. 월요일에 완료 기준이 명확한 핵심 목표 3개를 선정한다.
2. 버그는 P0(보안·데이터 손실·전체 장애), P1(핵심 기능), P2(일반 개선), P3(장기 후보)로 분류한다. P0는 요일에 관계없이 우선 대응한다.
3. 세렌은 제안 → 선정 → 구현 → 테스트 → 완료로 상태를 구분한다.
4. 기존 기능·데이터 보존을 우선하고 변경 전 영향 범위를 확인한다.
5. 테스트하지 않은 변경은 배포하지 않는다. 실패한 작업은 다음 주로 이월한다.
6. 일요일에 목표 달성률, 해결한 버그, 배포 내역, 사용자 반응을 회고한다.
7. 주간 일정은 강제가 아니며 학업·휴식에 따라 조정할 수 있다.

- **SMART RETURN:** 최근 플레이 프로젝트 빠른 재진입

채택은 개발 후보 확정이지 배포 완료를 의미하지 않는다.
