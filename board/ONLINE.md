# Formwheel Board 온라인 대전 운영 안내

## 현재 구현

- 체스, 바둑(9/13/19줄), 오목(15×15 자유룰), 오델로(8×8)를 방 코드로 2명이 플레이합니다.
- 방 생성자는 백(체스)/흑(나머지), 참가자는 반대 색입니다.
- Firebase Realtime Database `boardRooms/{8자리 방코드}`에 순서대로 수를 저장합니다. 거래·Rapid·업적·랭킹에 영향을 주지 않습니다.
- 각 플레이어는 자기 턴에서만 UI로 착수 가능하며, 수순을 처음부터 재생하면서 기존 로컬 규칙으로 검증합니다.
- 동시에 수를 보낼 때는 Firebase 트랜잭션으로 최신 수순 길이를 확인합니다.
- 방 코드/초대 링크 공유, 새로고침·재접속, 로컬 모드로 나가기 지원. 브라우저에 기록된 계정과 같은 Firebase UID로만 다시 입장할 수 있습니다.

## 운영 준비 (GitHub 업로드만으로는 불충분)

1. Firebase Console → **Authentication → Sign-in method**에서 **Anonymous** 또는 해당 사용자들의 Google 로그인을 활성화합니다. Google 로그인은 Hub에서 마친 뒤 Board로 돌아오면 됩니다.
2. Firebase Console → Realtime Database → **Rules**에서 현재 운영 중인 전체 Rules를 먼저 백업합니다.
3. 저장소 `database.rules.json`의 **`rules.boardRooms` 부분만** 운영 Rules에 병합합니다. **저장소의 전체 파일로 운영 Rules를 덮어쓰지 마세요.** 다른 게임에서 쓰는 운영 규칙이 저장소와 다를 수 있습니다.
4. Firebase Rules 테스트/에뮬레이터에서 방 생성, 두 번째 사용자 참가, 양측 번갈아 착수, 타인 접근 거부 및 기존 게임 기능이 유지되는지 확인한 뒤 적용합니다.
5. 서로 다른 브라우저/계정에서 `https://semicolonxss.github.io/Formwheel/board/`에 접속해 실제 온라인 동기화를 확인합니다.

**운영 Rules 배포는 이 GitHub 커밋에 포함되어 있지 않습니다.** 권한 오류가 뜨면 먼저 Firebase의 실제 배포 규칙을 확인하세요.

## 보안·제한

- 인증 UID·방 코드 검증, 참가자 제한, 지정 경로만 쓰기, 입력 범위/수순 길이 제한이 있습니다.
- **친선 대전용**입니다. 규칙은 데이터 모양과 참가자를 제한하지만 **체스·바둑·오목·오델로의 완전한 합법수 판정은 클라이언트에서 수행**합니다. 조작된 클라이언트가 악의적인 수를 보낼 수 있으므로, 이 기록을 순위/보상/경제 시스템에 사용하지 마세요.
- 해당 수준의 공정성이 필요하다면 서버 측의 권위 있는 수 검증(Cloud Functions 등)을 추가해야 합니다.
- 방은 자동 만료/삭제되지 않습니다. 운영 시 TTL 정리 작업이 필요합니다.
- 온라인에서는 무르기, 대국 재시작, AI, 재대국 투표, 관전, 채팅, 승률 및 토너먼트 기능은 지원하지 않습니다.
- 바둑 계가는 간이 중국식이며 자동 사석 합의가 없어 공식 결과와 차이가 날 수 있습니다.

## 수동 검사 시나리오

1. A 체스 방 생성 → 8자리 코드 확인 → B 코드 참가.
2. A의 e2-e4 → B 화면 반영 → B e7-e5 → A 화면 반영.
3. A가 B 차례에 두려고 하면 입력 불가. 2명 찬 방에는 C 참가 불가.
4. A 또는 B 새로고침 → 같은 Firebase UID로 방 코드를 다시 입력해 재접속.
5. 체스 체크, 캐슬링, 앙파상, 승격, 무승부 확인.
6. 바둑 착수·따냄·패스, 오목 5목 승리, 오델로 반전/자동 패스 확인.
7. 로컬 모드로 돌아간 뒤 기존 게임들이 모두 정상 작동하는지 확인.
